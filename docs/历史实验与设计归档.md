# 历史实验与设计归档

本文档用于保存“对追溯有价值，但不再适合放在主入口文档中的内容”。

使用原则：

- 当前状态、当前命令、当前参数口径，以 `README.md`、`ICL_OpenHermes_TODO.md`、`评测方案.md`、`MIG_标签图操作指南.md` 为准。
- 本文档只用于回答两类问题：
  - 过去为什么做过某个设计选择
  - 某次历史实验当时是怎么跑的
- 本文档里的旧参数、旧默认值、旧路径名，不应直接复用到新实验。

---

## 1. 被归档的内容类型

这次文档重构时，主文档里主动移出的主要是三类内容：

1. 带日期的会话流水账
2. 局部 TODO 文档中的重复设计说明
3. 已经过时、但仍有历史解释价值的命令口径

这样做的目的是让主文档更像“当前项目操作台”，而不是“完整聊天记录”。

## 3. 已删除局部 TODO5 的归档摘要

原 `ICL_TODO5_query_aware_selector_design.md` 已并入主文档，不再单独维护。  
但其中有几条“帮助理解实现演化”的信息值得保留在这里。

### 3.1 当时的定位

原 TODO5 的目标是为 query-aware ICL 选例器提供一份单独设计草案，核心范围包括：

- 按 query 选择 `K` 条示例
- 保留 MIG 的信息增益与边际递减思想
- 说明 query 标签、候选样本表示、惩罚项与输出接口

### 3.2 当时强调的代码对齐关系

原文档明确建议尽量复用以下模块，而不是重写底层能力：

- `mig/data.py`
- `mig/label.py`
- `mig/sampler.py`
- `mig/icl_data.py`

同时建议新增：

- `mig/icl_selector.py`
- （可选）`mig.cli` 的 `select-icl` 子命令

### 3.3 当时保留的 query 打标签原则

局部 TODO5 里有一条现在仍然重要的原则：

- query 标签应优先沿用 `InsTagger -> 归一化 -> 映射到 valid_tag_path` 的离线路线
- 不建议把 query 标签主流程退化成临时规则抽取

这条原则现在已经体现在主文档的“稳定口径”里，但这里保留其设计来源。

### 3.4 当时保留的难度建模思路

原 TODO5 对候选池难度的建议是：

1. 复用 OpenHermes 中已有的 `annotation.deita.complexity_scores`
2. 用聚合值生成单个 `difficulty_score`
3. 先按分位数离散成 `easy / medium / hard`
4. 难度向量独立建模，不经过语义传播矩阵

这部分现在仍然是当前实现与后续实验的重要背景。

### 3.5 当时的早期打分式

原 TODO5 曾把打分写成下面这种更“工程接口化”的形式：

```text
score(i | S, q) = gain + lambda_quality * q_i - lambda_len * P_len - lambda_red * P_red - lambda_diff * P_diff
```

这不是当前唯一权威写法，但它很好地说明了项目早期是如何把：

- 增益
- 质量
- 长度
- 冗余
- 难度

这五类因素接到一个统一打分接口里的。

### 3.6 当时考虑过的加速思路

原 TODO5 里还保留过一个“先 Top-M 预筛，再做贪婪”的想法：

- 先按 `prior_i = <z_i A, w_q>` 取 Top-M
- 再在 Top-M 里做贪婪选择

这条思路对理解算法演化有用，但它不是当前主文档里的稳定默认流程。

## 4. 旧参数与旧口径提醒

下面这些内容在历史文档里出现过，但现在不应被当成默认值：

- `k = 8`
  - 早期局部设计文档里常出现 `k=8`
  - 当前实际评测主线已切到 `k=5`

- `top_m = 2000`
  - 属于早期加速设想
  - 不是当前稳定主流程默认项

- APPS 的 function-only prompt
  - 已废弃
  - 当前必须使用完整程序口径

- 旧 run name
  - 如 `v32_mig_k5_full`
  - 只表示当时那次实验，不应被机械复用

- 旧 cache 路径写法
  - 历史文档里可能会写在 `data/icl/cache/`
  - 当前更建议统一放在项目根目录 `cache/`
