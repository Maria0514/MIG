## 1. 设计目标

当前设计的核心目标是：

- 把 MIG 的“信息增益 + 边际递减”思想迁移到 query-aware ICL 选例。
- 让示例选择同时考虑：
  - query 相关性
  - 标签特异性
  - 样本质量
  - 示例长度
  - 冗余度
  - 难度分布（预留）

---

## 2. 核心定义

- \(G=(V,E)\)：语义标签图
- \(L_q \subseteq V\)：Query 的标签集合
- \(D=\{d_i\}_{i=1}^{N}\)：候选示例池
- \(df(l)\)：标签 \(l\) 在候选池中的文档频次
- \(s_i\)：样本 \(i\) 的信息密度分数
- \(A\)：语义传播矩阵
- \(c_i\)：样本 \(i\) 的难度分数

样本最终表示由两部分组成：

\[
v_i = v_i^{sem} \ \Vert\ v_i^{diff}
\]

其中：

- \(v_i^{sem}\)：语义标签部分
- \(v_i^{diff}\)：难度标签部分

---

## 3. Query 权重设计

对每个标签 \(j\) 计算一个 query 需求权重 \(w_j(q)\)，由两部分组成：

### 3.1 相关性

\[
R_j(q)=
\begin{cases}
1, & dist(l_j, L_q)=0\\
0.5, & dist(l_j, L_q)=1\\
0, & dist(l_j, L_q)\ge 2
\end{cases}
\]

它表达的是：标签和 query 越接近，权重越高。

### 3.2 特异性

\[
S_j = \mathrm{idf}(l_j)=\log\frac{N+1}{df(l_j)+1}
\]

它表达的是：越稀有的标签，信息量越大。

### 3.3 合成权重

当前思路上，query 标签权重可以理解为：

\[
w_j(q) \propto R_j(q)\cdot S_j
\]

这保证：

- 与 query 无关的标签被压低
- 与 query 相关且稀有的标签被放大

## 4. 统一目标函数

对样本集合 \(S\)，定义累积信息向量：

\[
x(S)=\sum_{i\in S}\hat e_i
\]

每个样本的统一信息向量：

\[
\hat e_i \triangleq \left(A\cdot e_i^{sem}\right)\ \Vert\ \left(\lambda\cdot e_i^{diff}\right)
\]

其中：

- \(e_i^{sem}=s_i\cdot v_i^{sem}\)
- \(A\cdot e_i^{sem}\) 表示语义传播后的信息
- \(e_i^{diff}\) 表示难度部分
- \(\lambda\) 控制难度维度的重要性

全局目标函数：

\[
F(S;q)=\sum_j w_j(q)\cdot \phi(x_j(S))
\]

其中 \(\phi\) 是单调递增的凹函数，例如：

- \(\phi(x)=\log(1+x)\)
- \(\phi(x)=x^{0.8}\)

凹函数的作用是引入“边际收益递减”，避免示例都堆到同一类标签上。

## 5. 贪婪选择流程

输入：候选池 \(D\)、query 标签 \(L_q\)、目标示例数 \(K\)。  
输出：按顺序选出的示例集合 \(S\)。

流程：

1. 计算 query 权重向量 \(w(q)\)
2. 初始化 \(S=\varnothing\)，\(x=0\)
3. 对每个未选样本计算边际收益
4. 选取收益最大的样本加入 \(S\)
5. 更新 \(x\)
6. 重复到选满 \(K\) 条

边际收益形式：

\[
\Delta F(i\mid S)=\sum_{j\in supp(\Delta x(i))} w_j(q)\Big[\phi(x_j+\Delta x_j(i))-\phi(x_j)\Big]
\]

## 6. 难度建模设计

当前难度部分有三种层级，越往后越偏研究型：

### 6.1 三桶离散

最直接的版本：

\[
\mathcal{C}=\{Easy, Medium, Hard\}
\]

优点：

- 简单
- 可解释
- 便于快速做消融

### 6.2 连续分桶 + 平滑

把复杂度轴分成 bins，并用局部高斯核把一个样本的难度贡献扩散到邻近 bins。

适合：

- 希望难度覆盖更细粒度时

代价：

- 超参数更多
- 可解释性下降

### 6.3 KDE 连续密度

对已选集合的难度分布做 KDE，再对密度应用凹函数。

适合：

- 把“难度分布覆盖”建模成连续优化问题

代价：

- 计算更复杂
- 当前仓库尚未落地

## 7. 当前实现对齐

### 7.1 已对齐部分

- Query-aware 选例器已按“增益 + 边际递减”的主思路落地。
- 当前 HumanEval 主实验口径已经从原始 open-set `query_labels` 扩展到 projected 版本：先按现有 `normalize + alias + exact-match` 规则映射到当前图空间，再删除 `query_labels_graph=[]` 的样本，形成 `148` 条正式对比集。
- 长度惩罚已接入当前打分。
- 难度向量接口已预留。

### 7.2 当前长度惩罚口径

当前代码中的长度惩罚采用乘积模式：

\[
\mathrm{quality\_eff}_i=\mathrm{quality}_i\cdot \exp(-\beta\cdot \mathrm{len\_norm}_i)
\]

\[
\mathrm{score}_i=\mathrm{gain}_i+\lambda_{quality}\cdot \mathrm{quality\_eff}_i-\lambda_{red}\cdot \mathrm{red}_i
\]

其中：

- `lambda_len` 在代码里扮演 \(\beta\) 的角色
- `len_norm` 是长度经 `log1p + min-max` 后的归一化值
- 当前稳定默认值按 `lambda_len=0.3` 记录；`0` 主要用于关闭长度惩罚的消融。
- `lambda_len=0` 时，长度惩罚关闭

### 7.3 仍未完全对齐部分

- `lambda_diff` 对应的完整难度分布目标尚未落地
- 多种示例排序策略尚未系统对照
- 多步扩散与 Query 邻域约束尚未系统实验
- 理论式中质量分 \(s_i\) 是乘到语义表示上的；而当前代码实现中，质量分与长度惩罚是作为独立加法项进入贪婪打分。这两层口径目前并未完全统一，应在实验与写作中显式区分。

## 8. 当前保留的研究问题

### 8.1 排序策略

除了贪婪选择顺序，仍可继续比较：

1. 按单个示例对 query 的覆盖度排序
2. 按标签距离排序
3. 按 scorer 分数排序
4. 按 MIG 顺序的逆序排序

### 8.2 长度惩罚

至少保留两组：

1. `lambda_len = 0.0`
2. `lambda_len > 0`（例如 `0.3`）

### 8.3 多步扩散

仍可继续研究：

- \(A^k\) 的 k 步扩散
- 多步加权和（PPR/RWR）
- 限定在 Query 邻域中的扩散

### 8.4 质量项缩放与 Query 权重增强

当前一个值得重点验证的方向是：降低质量分 \(s_i\) 对选例的支配，提升 query 权重 \(w_j(q)\) 对标签命中的主导作用。

#### 理论层改法

原始理论写法中：

\[
e_i^{sem}=s_i\cdot v_i^{sem}
\]

若希望压缩质量分范围，可定义：

\[
\tilde s_i=(1-\rho)+\rho s_i,\qquad \rho\in[0,1]
\]

再改为：

\[
e_i^{sem}=\tilde s_i\cdot v_i^{sem}
\]

此时：

- \(\rho=1\) 时退化为原始公式
- \(\rho=0\) 时样本质量完全不起作用
- \(0<\rho<1\) 时质量仍保留，但动态范围被压缩

若希望进一步放大 query 需求权重，可定义 sharpening：

\[
\tilde w_j(q)=\frac{w_j(q)^{\kappa}}{\sum_t w_t(q)^{\kappa}},\qquad \kappa\ge 1
\]

并把目标函数写为：

\[
F(S;q)=\sum_j \tilde w_j(q)\cdot \phi(x_j(S))
\]

#### 当前实现层改法

当前代码中的实际贪婪打分更接近：

\[
\mathrm{score}_i=\mathrm{gain}_i+\lambda_{quality}\cdot \mathrm{quality\_eff}_i-\lambda_{red}\cdot \mathrm{red}_i
\]

其中：

\[
\mathrm{quality\_eff}_i=\mathrm{quality}_i\cdot \exp(-\beta\cdot \mathrm{len\_norm}_i)
\]

因此在当前实现框架下，对应的可研究改法是：

1. 直接减小 \(\lambda_{quality}\)
2. 先压缩 `quality` 的动态范围，再进入 `quality_eff`
3. 在不改图空间的前提下，对 query 权重 \(w_j(q)\) 做 sharpening，使 `gain` 更集中地反映标签命中

该方向的核心动机是：当前 `MIG` 在 HumanEval 上仍倾向选择较长、较难、较工程化的示例；若质量项过强，可能会压过 query 标签命中带来的增益。

## 9. 适用范围

当前文档的默认目标任务是 Python 代码生成，特别是：

- HumanEval：函数补全
- APPS(test)：完整程序生成

如果未来迁移到别的任务，本设计中最需要重新确认的是：

1. Query 标签质量
2. 标签空间是否仍有区分度
3. 长度惩罚是否仍然合理
4. 难度定义是否仍然可复用
