# MIG-ICL 评测方案

本文档只负责评测闭环的稳定协议，不记录会话历史。  
当前项目状态、最新结果和待办请看 [ICL_OpenHermes_TODO.md](./ICL_OpenHermes_TODO.md)。

---

## 1. 评测目标

评测闭环要回答三个问题：

1. `MIG-ICL` 相比 `Zero-shot / Random / Similarity` 的效果如何。
2. HumanEval 与 APPS 两类任务是否都能走通统一的产物和评测口径。
3. 每次运行是否都能被复现、追溯和对比。

---

## 2. 数据与任务口径

### 2.1 固定输入文件

- 候选池：`data/icl/openhermes_python_related.jsonl`
- HumanEval Query：`data/icl/humaneval_eval_tagged.jsonl`
- HumanEval 严格投影对比集：`data/icl/humaneval_eval_tagged_projected.jsonl`
- APPS Query：`data/icl/apps_test_eval_tagged.jsonl`
- 主配置：`configs/icl_eval_config.json`

当前统一推理口径：

- 所有方法默认 `max_tokens=2048`
- 当前正式限流口径：`parallelism=2`、`rate_limit_qps=0.6`、`bucket_capacity=1`、`retry=5`、`retry_backoff_s=8`

### 2.2 两类任务的根本区别

- HumanEval
  - 任务形式：函数补全
  - 判分方式：执行 `tests.test`
  - 生成口径：只补函数体/函数定义相关代码

- APPS
  - 任务形式：完整程序
  - 判分方式：执行 `tests.input_output`
  - 生成口径：完整程序 + `stdin/stdout`

不要把 APPS 当成 HumanEval 去跑；两类任务的 prompt 模板、判分方式和生成口径仍然不同。

### 2.3 HumanEval 当前正式对比口径

- 若目标是比较 `Zero-shot / Random / Similarity / MIG` 四种方法本体差异，当前 HumanEval 应优先使用 `data/icl/humaneval_eval_tagged_projected.jsonl`。
- 这份 projected 文件已经删除 `16` 条 `query_labels_graph=[]` 的样本，当前正式对比集大小为 `148`。
- 这样做的原因不是数据清洗便利，而是避免 `MIG` 在空合法标签 query 上退化成无 query 信号的默认贪婪选例，从而污染方法比较。

### 2.4 Query 最小必需字段

每条 query 至少应包含：

1. `id`
2. `prompt`
3. `tests`
4. `entry_point`
5. `query_labels`
6. `source`

## 3. 实验分组

当前标准分组：

1. `Zero-shot`
2. `Random-ICL`
3. `Similarity-ICL`
4. `MIG-ICL`

当前默认建议：

- `k=5`
- `pass@1` 先跑全量
- `pass@5` 只在每题 completion 数达到 `n>=5` 时再统计

可选消融：

- `MIG-no-len`
- `MIG-no-red`
- `MIG-no-idf`
- 后续如果难度项落地，再加 `MIG-no-diff`

## 4. 产物目录规范

### 4.1 Prompt

- `data/icl/eval_prompts/<method>_<task>_k<k>.jsonl`

示例：

- `data/icl/eval_prompts/mig_humaneval_k5.jsonl`
- `data/icl/eval_prompts/random_apps_test_k5.jsonl`

### 4.2 推理输出

- `data/icl/eval_outputs/<run_name>/outputs.jsonl`
- `data/icl/eval_outputs/<run_name>/run_manifest.json`

### 4.3 评测输出

- `data/icl/eval_metrics/<run_name>/summary.json`
- `data/icl/eval_metrics/<run_name>/per_query.jsonl`
- `data/icl/eval_metrics/<run_name>/per_sample.jsonl`
- `data/icl/eval_metrics/<run_name>/failed_cases.jsonl`
- `data/icl/eval_metrics/<run_name>/run_manifest.json`

### 4.4 运行命名建议

`run_name` 建议显式包含以下信息：

- 日期或批次
- 任务集（`humaneval` / `apps_test`）
- 方法（`zero/random/sim/mig`）
- `k`

示例：

- `20260329-humaneval-mig_k5`
- `20260329-apps_test-random_k5`

## 5. 标准命令链路

标准链路是：

1. 生成 `query -> demo` 映射
2. 组装 prompts
3. 调 API 推理
4. 自动评测
5. 汇总报告

下面只保留稳定入口。

## 6. Prompt 组装

脚本：`utils/build_icl_prompts.py`

### 6.1 HumanEval 示例

```powershell
.\.venv\Scripts\python.exe utils/build_icl_prompts.py `
  --pool data/icl/openhermes_python_related.jsonl `
  --queries data/icl/humaneval_eval_tagged_projected.jsonl `
  --mapping data/icl/mappings/humaneval_to_demos.jsonl `
  --config configs/icl_eval_config.json `
  --method mig `
  --out data/icl/eval_prompts/mig_humaneval_k5.jsonl
```

### 6.2 APPS 示例

```powershell
.\.venv\Scripts\python.exe utils/build_icl_prompts.py `
  --pool data/icl/openhermes_python_related.jsonl `
  --queries data/icl/apps_test_eval_tagged.jsonl `
  --mapping data/icl/mappings/apps_test_random_k5.jsonl `
  --config configs/icl_eval_config.json `
  --method random `
  --out data/icl/eval_prompts/random_apps_test_k5.jsonl
```

### 6.3 参数解释

- `--pool`
  - 候选示例池。通常固定为 OpenHermes Python 池。

- `--queries`
  - 当前任务的 query 文件。
  - HumanEval 和 APPS 不能混用。
  - 当前 HumanEval 四方法正式对比优先使用 `data/icl/humaneval_eval_tagged_projected.jsonl`。

- `--mapping`
  - 选例映射文件。
  - 必须与当前 `method + task + k` 一致。

- `--config`
  - 读取 `prompt_profiles` 和 `generation_profiles`。
  - 如果配置变了，同一条命令的行为可能也会变。

- `--method`
  - 当前 prompt 属于哪种方法，用于产物标记与 `k` 解析。

- `--k`
  - 是“期望 demo 数量校验”，不是任意截断开关。
  - 若不显式传入，会尝试从 `configs/icl_eval_config.json` 的 `k_by_method` 读取。

- `--prompt-task`
  - 仅在自动识别失败时才手动指定。
  - 常见值是 `humaneval` 或 `apps_test`。
  - 不要把 APPS 强行组成 HumanEval 模板。

- `--truncate-to-k`
  - 兼容旧行为时才使用。
  - 默认不应依赖它来“修正错误 mapping”。

- `--out`
  - 必须是新的、与当前任务匹配的 prompt 文件，不要覆盖旧实验。

## 7. API 推理

脚本：`utils/run_api_infer.py`

### 7.1 通用示例

```powershell
.\.venv\Scripts\python.exe utils/run_api_infer.py `
  --prompts data/icl/eval_prompts/mig_humaneval_k5.jsonl `
  --config configs/icl_eval_config.json `
  --run-name 20260329-humaneval-mig_k5
```

### 7.2 关键参数解释

- `--prompts`
  - 输入 prompt JSONL。

- `--run-name`
  - 运行名。
  - 不要复用旧值，否则很难区分目录。

- `--out`
  - 如果不传，会在 `base-out-dir/run-name/` 下自动生成。
  - 显式传入时要确认不会覆盖历史输出。

- `--model`
  - 当前默认 `nvidia/openai/gpt-oss-120b`。
  - 只有在明确切模型时才改。

- `--base-url`
  - 当前默认 `https://inference-api.nvidia.com`。

- `--api-key-env`
  - 当前默认读取环境变量 `SILICONFLOW_API_KEY`。
  - 默认会先加载项目根目录 `.env`，再从该环境变量取 key；文档不重复记录 key 明文。

- `--max-tokens`
  - `<= 0` 时，按当前统一默认值 `2048` 处理。
  - 当前文档口径是：所有方法默认 `max_tokens=2048`。
  - `configs/icl_eval_config.json` 中的 `default / humaneval / apps_test` 也已经统一到 `2048`。
  - 如需使用别的值，必须在命令与结果目录中显式标明。

- `--temperature`
  - `pass@1` 常用 `0.0`
  - `pass@k` 采样时才提高

- `--parallelism`
  - 并发 worker 数
  - 当前正式默认 `2`
  - 受 API 配额和机器资源约束，不是越大越好

- `--rate-limit-qps`
  - 请求限流速度
  - 当前正式默认 `0.6`
  - 需要根据服务商配额和报错情况调整

- `--bucket-capacity`
  - 令牌桶突发容量
  - 当前默认 `1`
  - 过大可能在短时间内触发服务端限流

- `--retry`
  - 当前默认 `5`
  - 遇到短时 `429` 或瞬时拥塞时会按重试策略补发

- `--retry-backoff-s`
  - 当前默认 `8`
  - 重试等待时间过短时，容易连续撞上同一轮限流

### 7.3 Nvidia 端点下的正式推理参数

当前统一正式口径如下：

- `--parallelism 2`
- `--rate-limit-qps 0.6`
- `--bucket-capacity 1`
- `--retry 5`
- `--retry-backoff-s 8`
- `--max-tokens 2048`

说明：

- 这是当前 HumanEval / APPS、`zero / random / sim / mig` 统一使用的正式推理口径。
- 这组参数比旧的 `parallelism=1 / rate_limit_qps=0.3` 更快，但比 `parallelism=4 / rate_limit_qps=1.0 / bucket_capacity=2` 更不容易触发 `429`。
- 如果仍频繁出现 `Priority-based rate limit exceeded` 或 `Model capacity reached`，应在具体实验记录中显式注明临时降回更保守口径，而不是默认再维护第二套正式参数。

- `--query-limit`
  - `0` 表示全量
  - 调试时常改成小值，正式运行前必须确认

- `--resume`
  - 只在明确想续跑同一个输出文件时使用

- `--selector-meta`
  - 选例元数据文件
  - 应该与当前映射文件匹配

## 8. HumanEval 评测

脚本：`utils/eval_humaneval.py`

### 8.1 示例

```powershell
.\.venv\Scripts\python.exe utils/eval_humaneval.py `
  --inference data/icl/eval_outputs/20260329-humaneval-mig_k5/outputs.jsonl `
  --prompts data/icl/eval_prompts/mig_humaneval_k5.jsonl `
  --k-list 1,5 `
  --run-name 20260329-humaneval-mig_k5_eval
```

### 8.2 参数解释

- `--inference`
  - 推理输出 JSONL。

- `--prompts`
  - 必须与推理时使用的 prompt 文件一致。

- `--k-list`
  - 要报告的 `pass@k`。
  - 如果每题只有 1 个 completion，则只应认真解读 `pass@1`。

- `--timeout-s`
  - 单条样本评测超时。
  - 机器慢时可能需要适当增大。

- `--max-samples-per-query`
  - `0` 表示使用该 query 的全部 completion。
  - 若开启采样评测，不能误设成过小值。

## 9. APPS 评测

脚本：`utils/eval_apps.py`

### 9.1 示例

```powershell
.\.venv\Scripts\python.exe utils/eval_apps.py `
  --inference data/icl/eval_outputs/20260329-apps_test-mig_k5/outputs.jsonl `
  --prompts data/icl/eval_prompts/mig_apps_test_k5.jsonl `
  --selector-meta data/icl/metadata/apps_test_to_demos.meta.json `
  --run-name 20260329-apps_test-mig_k5_eval `
  --k-list 1,5 `
  --timeout-s 10
```

### 9.2 参数解释

- `--inference`
  - APPS 推理输出 JSONL。

- `--prompts`
  - 必须使用 APPS prompt 文件，不能传 HumanEval prompt。

- `--selector-meta`
  - 应与当前 APPS mapping 匹配。

- `--run-name`
  - 建议带 `apps_test` 前缀，避免和 HumanEval 混淆。

- `--timeout-s`
  - APPS 通常比 HumanEval 更容易出现运行时间波动。
  - 过低会误伤正确程序，过高会拖慢整体评测。

- `--not-mig-algorithm`
  - 只在评测 baseline 方法时传。

### 9.3 APPS 特有注意事项

- APPS 不做 `prompt + completion` 拼接执行。
- APPS 直接把模型生成结果当完整程序跑。
- APPS 的 `tests.input_output` 必须存在，否则该 query 不应进入 APPS 评测链路。

## 10. Baseline 入口

### 10.1 单独生成 baseline 映射

脚本：`utils/build_baseline_mappings.py`

典型用途：

- `zero`：空示例
- `random`：固定种子随机抽样
- `sim`：embedding 相似度检索

这部分更具体的命令和缓存说明请看 [MIG_标签图操作指南.md](./MIG_%E6%A0%87%E7%AD%BE%E5%9B%BE%E6%93%8D%E4%BD%9C%E6%8C%87%E5%8D%97.md)。

### 10.2 一键 baseline pipeline

脚本：`utils/run_baseline_pipeline.py`

适合：

- 快速重跑 `zero/random/sim`
- 自动落盘 `mapping -> prompt -> infer -> eval -> report`

注意：

- `--k` 可能被 `configs/icl_eval_config.json` 中的 `k_by_method` 覆盖。
- `--query-limit` / `--pool-limit` 仅适合调试，不要忘记恢复为 `0`。
- 相似度方法的 `embedding-device / embedding-batch-size / cache` 必须按当前机器确认。
- `sim` 正式运行时，默认同时显式提供与当前候选池对应的 `--pool-emb-cache` 和与当前评测集对应的 `--query-emb-cache`；不要跨任务集混用 cache。
- 这两类 cache 默认都放在项目根目录 `cache/`。
- 对当前 HumanEval `projected148` 对比集，优先使用：
  - `cache/openhermes_e5m7b_pool_emb_f16.npy`
  - `cache/humaneval_projected148_e5m7b_query_emb_f16.npy`
- 当前代码也已兼容“用 `164` 条 HumanEval 老 cache 直接裁出 `148` 条 projected 子集”的 fast path；若 cache meta 中的 query id 覆盖当前 query 文件，则不会再因为 `shape mismatch` 回退到加载 embedding 模型。

## 12. 执行顺序建议

1. 先小样本冒烟。
2. 再跑全量 `pass@1`。
3. 最后跑采样版 `pass@k` 与消融。
4. 每次运行固定新的 `run_name` 和对应配置快照。
5. APPS 先验证小样本，再扩到全量 `5000` 条。
