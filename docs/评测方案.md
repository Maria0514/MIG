# MIG-ICL 评测方案

本文档定义当前项目的 ICL 选例评测闭环，覆盖：数据输入、实验分组、API 调用、提示词组装、自动评测与结果沉淀。

---

## 1. 评测目标

1. 验证 `MIG-ICL` 相比基线（`Zero-shot / Random / Similarity`）是否提升 HumanEval 代码生成效果。
2. 输出可复现指标：`pass@1`、`pass@k`、平均 token、平均延迟。
3. 沉淀可追溯产物：prompt、模型原始输出、评测明细、汇总报告。

---

## 2. 数据与输入

### 2.1 固定数据

1. 候选池：`data/icl/openhermes_python_related.jsonl`
2. Query 集：`data/icl/humaneval_eval_tagged.jsonl`
3. 各方法映射：
   - MIG：`data/icl/mappings/humaneval_to_demos.jsonl`
   - Zero：`data/icl/mappings/humaneval_zero_k0.jsonl`
   - Random：`data/icl/mappings/humaneval_random_k5.jsonl`
   - Similarity：`data/icl/mappings/humaneval_sim_k5.jsonl`
4. 参数记录：
   - MIG：`data/icl/metadata/humaneval_to_demos.meta.json`
   - Baseline：`<mapping>.meta.json`

### 2.2 Query 字段

最小必需字段：
1. `id`（query_id）
2. `prompt`
3. `tests.test`
4. `entry_point`
5. `query_labels`（用于可解释分析，不直接用于 HumanEval 判分）

---

## 3. 实验分组

默认建议 `k=5`（当前已验证全量结果），至少做 4 组：

1. `Zero-shot`
2. `Random-ICL`
3. `Similarity-ICL`（文本 embedding 检索 top-k）
4. `MIG-ICL`（按 `ordered_demo_ids` 顺序）

可选消融组：
1. `MIG-no-len`（`lambda_len=0`）
2. `MIG-no-red`（`lambda_red=0`）
3. `MIG-no-idf`（relevance only）

---

## 4. Prompt 组装规范

### 4.1 统一 system 指令

建议固定为：

```text
You are a Python coding assistant. Complete the target function correctly.
Output only Python code with no markdown fences and no explanation.
```

### 4.2 ICL 示例模板

每条示例由候选池一条样本映射得到：

```text
[Example i]
Problem:
{demo_user_content}

Reference Solution:
{demo_assistant_content}
```

说明：
1. `demo_user_content` 与 `demo_assistant_content` 来自 `dialogs`。
2. 若包含 ``` 代码围栏，组装前去掉围栏。
3. 若超上下文，先保留前序示例（尤其 MIG 顺序前部）。

### 4.3 Query 模板

```text
[Target Problem]
{humaneval_prompt}

Please provide the completion for the target function only.
```

## 5. API 调用方案

### 5.1 调用原则

1. 所有实验组使用同一模型版本、同一 API 基址。
2. `pass@1` 使用确定性设置（如 `temperature=0`）。
3. `pass@k` 使用采样设置（如 `temperature=0.8, n=20`）。
4. 对失败请求做有限重试（如最多 2 次），并记录错误码。
5. 建议启用并发 + 令牌桶限流（避免突发请求超限）。

### 5.3 当前实现（仓库脚本）

脚本：`utils/run_api_infer.py`

1. 默认模型：`deepseek-ai/DeepSeek-V3.2`
2. 默认接口：`https://api.siliconflow.cn/v1`
3. 并发参数：`--parallelism`
4. 限流参数：`--rate-limit-qps`、`--bucket-capacity`
5. 每次运行自动创建独立目录并写 `run_manifest.json`

补充脚本（baseline 相关）：
1. `utils/build_baseline_mappings.py`：生成 `zero/random/sim` 的 `query -> demo` 映射。
2. `utils/run_baseline_pipeline.py`：一键串联 baseline 全流程（mapping/prompts/infer/eval/report）。

### 5.2 建议记录字段

每条推理结果至少包含：

1. `run_name`
2. `method`（zero/random/sim/mig）
3. `query_id`
4. `model`
5. `temperature`
6. `seed`（如支持）
7. `demo_ids`
8. `prompt_text`
9. `raw_output`
10. `completion_cleaned`
11. `latency_s`
12. `token_usage`（如 API 可返回）

---

## 6. 输出后处理

对模型输出执行标准清洗：

1. 去掉 markdown 代码围栏。
2. 去掉非代码前后缀（解释性文本）。
3. 保障可执行拼接（`prompt + completion`）。
4. 标记失败类型：`empty_output`、`syntax_error`、`runtime_error`、`timeout`。

---

## 7. 自动评测

### 7.1 HumanEval 判分

1. 使用每题 `tests.test` 执行单元测试。
2. `pass@1`：每题 1 个 completion。
3. `pass@k`：每题采样 `n` 个 completion 后计算 `pass@k`。
4. 执行需隔离环境 + 超时保护。

### 7.2 汇总指标

必报指标：
1. `pass@1`
2. `pass@k`（至少 `k=5`）
3. 平均输入 token
4. 平均输出 token
5. 平均延迟
6. 解析失败率与运行时失败率

补充说明（避免误读）：
1. 每题仅 1 个 completion 时，本质只得到有效 `pass@1`。
2. 此时 `pass@5_topk_any_available` 会退化为 `pass@1`（因为前 5 个里实际只有 1 个样本可用）。
3. 有效 `pass@5`（strict/estimator）要求每题至少 `n>=5` 个 completion。

## 10. 执行顺序建议

1. 先跑小样本冒烟（前 10 题）验证流程。
2. 再跑全量 164 题 `pass@1`。
3. 最后跑采样版 `pass@k` 与消融。
4. 每次运行固定 `run_name` 与配置快照，确保可追溯。
